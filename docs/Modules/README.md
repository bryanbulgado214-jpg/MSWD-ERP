# Modules

Whole-feature documentation, one file per module/phase, consolidating
everything about it — schema, services, APIs, workflow, UI, validation,
testing — in a single place. This is a deliberate complement to the
category-based folders elsewhere in `docs/` (`04_Database`, `06_API`,
`07_UI_UX`, etc.), not a replacement for them: those folders remain the
place for cross-cutting, project-wide standards (naming conventions, API
design conventions, the overall database architecture), while a document
here answers "what does the Budgeting module actually consist of, end to
end?" without making the reader assemble that picture from seven
different category folders themselves.

When a module reaches a natural checkpoint (a phase boundary, a release),
add or update its file here summarizing the current state, and list
every file created or modified to get there — this is the answer to
"what did we actually build" for that phase.
